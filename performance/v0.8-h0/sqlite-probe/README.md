# H0 SQLite comparison probe

This directory is an investigation-only harness. It does not replace the
production SQLite adapter and deliberately has no dependency on the root Go
module. It runs the same synthetic, production-shaped workload against:

* the SQLite 3.53.4 amalgamation (public-domain source, SHA3-256
  `628a44cfe82c66aed1ccbbe85a562d2e33ebe64b3288981ed76285612227934e`), and
* `modernc.org/sqlite` v1.57.0 (SQLite 3.53.3) with `modernc.org/libc`
  v1.74.4.

The workload creates notes, revisions, tags, FTS5 content, and JSON metadata;
it checks WAL, integrity, checkpoint/reopen, and performs a C -> modernc -> C
file round trip. `run.sh` keeps all downloads, builds, databases, and output
under a temporary directory. Nothing generated by the probe is intended for
version control.

## Reproduce

```sh
./run.sh                         # uses the existing Go module cache when possible
SQLITE_PROBE_KEEP=1 ./run.sh    # preserve the temporary evidence directory
```

The script does not silently substitute the system SQLite library: it verifies
the official amalgamation hash before compiling it. Set `SQLITE_PROBE_ARCHIVE`
to an already downloaded `sqlite-amalgamation-3530400.zip` for offline use.
Set `SQLITE_PROBE_GOPROXY=off` to require an already populated Go cache.

This is desktop-focused. Android cross-compilation/runtime evidence belongs to
the parent H0 task. The current probe uses a separate process lock file and
checks that a second owner is refused; that is a lifecycle proof, not a claim
that the production adapter already enforces this policy.

## Current limitations

The current store is a cgo wrapper around the C SQLite API in many files, so
the modernc run validates SQL/file compatibility and workload behavior rather
than the complete Notrios store package. It is intentionally not a production
migration. The modernc candidate is one SQLite patch release behind the
current upstream pin and must be upgraded/re-measured if its embedded version
changes.
