# v0.7 G13 — REST security foundation, pairing, and transport policy

G13 is production code. This directory holds the artifact the plan asked for:
the **authentication and authorization matrix**, generated by running every way
a request can arrive against a real service with a real enrolled peer, plus the
transport-policy decisions the service makes at startup.

It is a table on purpose. The test suite proves each control works; the matrix
is what someone reads against the threat model, and regenerates when the surface
changes.

## Reproduce

```bash
env GOCACHE=/tmp/notrios-g13-gocache go test ./internal/syncauth/... ./internal/httpapi/... \
  ./internal/store/... ./internal/config/... ./cmd/notriosctl/...

env GOCACHE=/tmp/notrios-g13-gocache \
  go run ./performance/v0.7-g13/cmd/matrix -out performance/v0.7-g13/auth-matrix.json

PYTHONDONTWRITEBYTECODE=1 python3 performance/v0.7-g13/validate_evidence.py
```

## Evidence

- `auth-matrix.json` — every case, the status it received, whether it was
  authorized, the reason recorded in the local audit log, and whether the reply
  explained itself;
- `FINDINGS.md` — what the matrix says, what pairing is and is not, and what
  this milestone deliberately does not claim.

## Safety

Every library, key, note, and code here is generated. No private corpus, no key
material, and no credential is read or recorded, and the committed report
contains no secret — the audit reasons are a closed vocabulary and the case
names describe request shapes rather than data.

## Scope

One host, in-process HTTP, and one enrolled peer. The cross-process evidence —
two compiled binaries, a running `notriosd`, a real pairing over the network,
and a startup refused for want of TLS — lives in `cmd/notriosctl`'s tests rather
than here, because it is a behavior to assert rather than a number to record.
