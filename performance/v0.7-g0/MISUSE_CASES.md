# Misuse cases and planned controls

Nothing in this table is a live synchronization control merely because G0 names
it. “Existing” identifies a v0.6 primitive that later work may reuse; all other
controls land in their owning G slices and must receive tests there.

| ID | Misuse / failure story | Required rejection or recovery behavior | Planned controls and owner |
|---|---|---|---|
| M01 | Hostile shared directory injects an invented envelope. | Reject before decrypt/apply; quarantine bounded evidence; do not advance state. | Canonical outer bytes, enrolled Ed25519 key lookup/signature, database/type/version binding (G9); bounded carrier staging (G11). |
| M02 | Carrier replaces visible database ID, source key ID, type, epoch, nonce, or length on valid ciphertext. | Signature or AEAD associated-data check fails; generic audited rejection. | Outer signature covers routing/ciphertext commitment and AEAD binds the same header (G9). |
| M03 | Carrier replays an old but correctly signed envelope or acknowledgement. | Exact duplicate is idempotent; stale/conflicting identity is refused; state never moves backward. | Replica sequence/state vectors (G5–G6), artifact IDs and domain separation (G9), retained replay/retirement floors (G16). |
| M04 | Carrier delivers envelope 12 before 10–11, forever or temporarily. | Keep only a bounded pending dependency; request gaps; never advance contiguous vector across them; snapshot-resync when bounds expire. | Contiguous vectors and pending bounds (G6), signed requests (G9), catch-up (G10), retry/job policy (G14). |
| M05 | Carrier/provider deletes or withholds all remote artifacts. | Local canonical state stays valid; recreate advertisements/envelopes or fetch from peer/backup; report unavailable rather than inventing success. | Durable journal (G5), reconstructible directory protocol (G11), snapshot catch-up (G10). Permanent loss of every canonical/backup copy remains unrecoverable. |
| M06 | Curious provider reads cloud directory and traffic. | It sees only the documented routing tuple, ciphertext sizes/timing/frequency, and opaque addresses; no note/resource plaintext or plaintext hashes. | Mandatory payload AEAD and metadata budget (G9), non-descriptive layout (G11), TLS plus payload encryption over REST (G12–G13). |
| M07 | Provider performs known-plaintext matching against visible resource SHA-256 names. | Plaintext content hashes remain encrypted; visible addresses identify ciphertext/artifact bytes if discovery needs them. | Format/layout choice (G9, G11); signed encrypted manifests reference inner plaintext hashes. |
| M08 | Compromised active replica sends a correctly signed mass deletion. | Operations remain attributed; user can revoke, rotate epoch, inspect conflicts/history, and restore/merge. It cannot be cryptographically classified as unauthorized while active. | Enrollment/revocation (G4), operation history and merge audit (G5–G7), revisions/tombstones/acks (G16), UI/recovery (G15). |
| M09 | Compromised or revoked replica retains a shared encryption key and reads future traffic. | Later artifacts use a new epoch not delivered to that replica; old epoch is rejected for new protocol positions. | Independent signing/encryption keys, recipient-scoped distribution, epoch advance on compromise (G9); secret management (G13). Historical data already held is residual risk. |
| M10 | Retired replica returns with years-old signed artifacts after peers compact history. | Refuse old identity/sequence against retained retirement floor; require re-enrollment/new identity and snapshot catch-up. | Durable retirement/death record (G4, G16), replay floor (G6/G16), catch-up (G10). |
| M11 | Copied SQLite database creates two writers with one replica ID and overlapping sequence numbers. | Refuse writable startup/sync until explicit adopt/fork/replace planning mints a safe identity; never merge by path or mtime. | Profile/path/ID collision detection (G3), transactional sequence allocator (G5), identity-bound envelope validation (G9). Existing archive restore planning already distinguishes adopt/fork/replace. |
| M12 | Malicious REST caller probes artifact IDs or supplies `/etc/passwd` as a snapshot path. | Require scoped auth; accept opaque IDs only; return generic not-found/forbidden behavior; never open a caller path. | Sync-only routes and opaque range fetch (G12), pairing/auth/TLS/quota/audit (G13). Current REST is loopback-only and not a substitute. |
| M13 | Valid REST credential for one database or sync route is used against ordinary note routes or another database. | Deny by route and database scope; no ambient administrator meaning. | Credential model and middleware (G13), separate sync APIs (G12), MCP boundary review (G14). |
| M14 | Attacker submits huge declared counts/sizes, deep JSON, dependency fan-out, many tiny objects, or slow ranges. | Reject at fixed gates before allocation/work; cap concurrent staging, requests, retries, connections, and disk. | Measured numeric bounds (G2), strict format/admission (G9), carrier and REST quotas (G11–G13), job/backpressure (G14). |
| M15 | Tiny authenticated ciphertext expands into a compression bomb supplied by a compromised enrolled replica. | Stream into quarantine with hard compressed/expanded/ratio/time/count limits; fail before canonical writes. | G2 selects limits; G9 enforces after signature/AEAD and before apply; G10 bounds snapshot extraction. |
| M16 | Attacker mutates object bytes but preserves the filename, or substitutes MIME/content. | Exact hash/size/MIME validation fails; references remain unavailable; no canonical admission. | Existing archive-v2 SHA-256, MIME sniffing, immutable objects, and pre-write verification; extended by G8–G10. Hash is integrity, not authorization. |
| M17 | Password-protected backup uses a weak password and is copied for offline guessing. | Use versioned Argon2id parameters/salt and AEAD; warn about offline risk; never log/store password; wrong password is a non-destructive generic error. | Parameter/device evidence (G2), format/crypto (G9), password UI and catch-up/restore (G10/G15). Exact KDF parameters are not frozen in G0. |
| M18 | User loses the only backup password. | Explain irrecoverability and offer other replica/backup recovery; no bypass, default password, retained plaintext key, or support backdoor. | Recovery UX (G10/G15), documentation (G20). Test decrypt at creation may catch typos, not forgotten passwords. |
| M19 | Pairing QR/file/link is copied, reused, or shown for the wrong database. | One-use and expiry; display database/key fingerprints and capabilities; require proof of possession and explicit confirmation; record refusal/expiry. | Enrollment protocol (G4), secret/audit integration (G13). Discovery is never enrollment. |
| M20 | Sender signs one serialization while receiver verifies a normalized equivalent, enabling type/confusion ambiguity. | Reject non-canonical or unknown-critical encodings; artifact domain/type/version is in signature context. | Deterministic encoders and golden fixtures (G9); protocol compatibility tests (G18). |
| M21 | Sender signs a hash only, and attacker rebinds the same object into a request/ack/snapshot role. | Each artifact has domain-separated canonical bytes; references bind database, role, and expected object metadata. | Signature coverage specification (G9). Content hashes never authenticate role or writer. |
| M22 | Nonce repeats under one AEAD key after crash/clone/concurrency. | Construction makes collision negligibly likely or derives uniqueness from durable identity/sequence; receiver rejects malformed reuse/conflict where observable. | G9 algorithm/nonce construction, G5 durable sequence allocation, crypto fault/golden tests. Exact algorithm choice remains G9. |
| M23 | Plaintext development mode is accidentally used against a remote service or production peer. | Refuse non-loopback binding and production protocol interoperability; no downgrade/fallback; prominent status/audit marker. | Explicit test-only provider/config and distinct protocol marker (G9/G13), install validation (G17). |
| M24 | Pairing, crypto, decompression, or decoder error includes secret bytes, note text, URL credentials, local path, or attacker-controlled terminal escapes. | Emit stable code and bounded redacted identifiers only; detailed local diagnostics sanitize control characters and remain local. | Audit/error contract (G9/G13), job/MCP redaction (G14), UI handling (G15). |
| M25 | Acknowledgement is forged or advanced before canonical durability, enabling GC of the last recovery state. | Only signed peer ack after durable contiguous apply counts; backup/snapshot is not an ack; GC remains dry-run, retention-delayed, reference-checked, all-active-peer gated. | Ack artifacts (G9), transaction boundary (G6), retention policy (G16). |
| M26 | A replica is kept “active” forever after being lost, preventing GC, or retired prematurely to force deletion. | UI reports horizon/blockers; retirement is explicit, confirmed, audited, and preserves a floor; GC dry run explains every peer dependency. | Peer UI (G15), acknowledgement-aware retention/retirement (G16). |
| M27 | Snapshot is complete but belongs to a different database/schema/capability/state-vector boundary. | Verify then refuse before canonical write; offer explicit fork/adopt only where semantically valid; never silently coerce. | Existing archive-v2 compatibility/identity verifier and explicit restore intent; sync bindings added in G9–G10/G18. |
| M28 | Snapshot manifest is visible before all objects or is replaced midway. | Ignore incomplete snapshot; publish manifest last; bind exact inventory/hashes/sizes; resumable ranges reverify bytes. | Existing archive-v2 manifest/object verification; snapshot protocol (G9–G10), carrier/REST atomic publication (G11–G12). |
| M29 | Filesystem watcher misses events, cloud mtime lies, or rename is not atomic. | Correctness follows explicit scan/poll/manual inventory and immutable hash-verified bytes; watcher only lowers latency. | Directory protocol (G11); rclone only performs optional non-destructive copy. |
| M30 | `rclone sync`, `bisync`, `move`, or purge deletes another peer's only artifact. | Such commands are never part of protocol correctness/tests; application deletion is an operation. | G11 conformance script allows only staged local copy or `rclone copy --immutable`; documentation/install guardrails (G17/G20). |

## Cross-cutting acceptance rules

- No decode, decrypt, decompress, hash, or signature operation receives an
  unbounded input. Cheap fixed-header and byte-count checks precede expensive
  work.
- No rejected or pending artifact advances a state vector, acknowledgement, or
  retention floor.
- No security failure falls back to a weaker algorithm, plaintext, another
  database/profile, or “best effort” merge.
- Quarantine and audit evidence is bounded; an attacker cannot fill disk merely
  by causing rejected inputs to be retained forever.
- Tests in G6/G9/G11/G12 shuffle, duplicate, replay, truncate, corrupt, and
  partition the same golden transcript across transports.
