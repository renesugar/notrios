# v0.4 P8 — Documentation and release wrap-up

Status: complete on 2026-08-05.

Model: Claude Opus 5 (Claude Code).

## Goal

Close the v0.4 milestone: user documentation that matches what J1–P7 actually
built, a deterministic offline Help reseed covering the two new pages, an
auditable v0.4.0 release checklist, the full validation suite, and a verified
source archive. Then draft the next plan from `ROADMAP.md` without starting it.

## Changes

- Bumped service, CLI, MCP, and web package metadata to `0.4.0`. The schema
  bootstraps and upgrades to v13.
- Added the v0.4.0 release-candidate and repository-owner sections to
  `RELEASE_CHECKLIST.md`, including the release boundaries a reader needs: a
  publication is a projection and not a backup, no external tool is yet verified
  to consume the handoff, `--pack` needs a reader that understands
  `objects.pack.v1`, an interrupted packed export restarts, and OS handler
  registration is Ubuntu-only.
- Reconciled the API implementation-status list with what is actually live over
  REST versus what is deliberately CLI-only (archive export/verify/restore,
  stable-link routing, publication).
- Updated `SECURITY_REVIEW.md` to cover publication handoffs — dropped link
  records, the stale-span refusal, the reviewed-plan gate, and the fact that a
  profile cannot name a command — and moved its header from v0.3 H10 to v0.4 P8.
- Verified the Help reseed: 15 pages seed, and a second run keeps all 15 and
  updates none, including the new `stable-links` and `publishing` guides.
- Archived the completed v0.4 plan as `plans/v0.4/000-v0.4-plan.md`, because it
  records reasoning the per-task files only reference: why P3a and P3b were
  sequenced before P4, why P6 was deferred, and what the document
  reconciliation corrected.
- Drafted the v0.5 plan in `PLAN.md` from `ROADMAP.md`. It is unstarted and
  requires user approval.
